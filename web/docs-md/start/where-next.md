# Choose your path

Choose one route based on what you need to do next.

## Learn WorkSpec from the beginning

Follow the nine-part [Learn WorkSpec path](/docs/learn/world-state/). It builds from world state to dynamic, causal behavior.

## Author a project now

Use the [WorkSpec language overview](/docs/workspec/overview/) as your lookup entry point. Its reference pages own exact fields, operations, and edge cases.

## Use terminal commands or automation

Start with the [CLI overview](/docs/cli/overview/). Use its command pages for options, output envelopes, and exit behavior.

## Build an integration

Start with the [JavaScript API overview](/docs/api/overview/). The API section documents only deliberately supported public symbols.

## Use visual tools

Start with the [WorkSpec Studio overview](/docs/studio/overview/) for editing, playback, Problems, assets, and visualization.

## Move an older project forward

Use [versions and compatibility](/docs/workspec/versioning-compatibility/) before you edit an older document. Compatibility syntax stays outside the canonical WorkSpec 2.2 learning path.

## Diagnose a failure

Start from the symptom in [Troubleshooting](/docs/troubleshooting/validation/). Use the `metric_id` field when you automate Problem handling.
